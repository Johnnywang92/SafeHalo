# Golden fixtures for the Python ↔ Rust equivalence suite

Small, committed regression oracles shared by both engines. The Python
production engine (`verify/ref_python.py` over `src/safehalo`) and the Rust
daemon must reproduce `golden/` byte-for-byte, and must agree with each other
event-by-event (`verify/compare.py`: same event types, exact timestamps,
floats within 1e-9 relative).

## Layout

```
gen_fixture.py            deterministic generator, all parameters documented inline
CHECKSUMS                 sha256 of the generated replay and of every golden file
generated/                regenerated on demand, gitignored
golden/flag_off/          trace.jsonl + snapshot.json with the feature flag OFF
```

`golden/flag_off/` is the "unchanged behaviour" oracle: any change to the
detection pipeline that leaves the flag off must still produce exactly these
files. When a gated feature ships, add a sibling directory (for example
`golden/object_confirm/`) rather than editing this one.

## Provenance and generation parameters

Nothing here was recorded in a real home. Every fixture is synthetic and
generated by `gen_fixture.py` from a fixed seed (`SEED = 20261110`) and a
single sequential RNG stream, so the output is byte-identical on any CPython
3.x. The signal model is the one already validated end-to-end against the
production engine by `verify/gen_replay.py` (52 subcarriers, 50 Hz, 86 % home
BSSID / 9 % weak neighbour / 5 % random MAC, ±1.5 ms jitter), truncated from
120 000 packets to 2 400 so the replay text stays around 1.2 MB and the golden
outputs stay a few kilobytes.

Two documented deviations from `gen_replay.py`, both chosen so the fixture
covers more of the state machine per byte:

| Parameter | gen_replay.py | gen_fixture.py | Why |
|---|---|---|---|
| locomotion doppler `sin(i / X)` | `X = 7.0` | `X = 4.0` | at 50 Hz `i/7.0` advances ~0.14 rad per frame, so walking never crosses `is_moving` and the fixture would miss `MOVING` |
| walk amplitude multiplier | `1.0` | `6.0` | same reason; `6.0` with `X = 4.0` reaches `MOVING` without tripping the high-impact clause on every walking frame |

The `main` fixture is 48 s: 5 s empty room (calibration) → 10 s walking →
12-packet impact transient → 33 s lying still with chest micro-motion. It
produces 53 trace events, 5 state transitions
(`EMPTY → STATIC → MOVING → FALL_SUSPECT → FALL_CONFIRMED`), one fall alarm
and the full targeted-inspection chain (burst request, respiration scan,
challenge, `VERDICT_FALL`).

## Running

```sh
sh verify/run_fixtures.sh          # generate, verify checksums, run both engines, compare
python3 fixtures/gen_fixture.py --list
```

## Regenerating a golden file

Only after confirming the new behaviour is intended:

```sh
python3 fixtures/gen_fixture.py                                  # writes generated/
TZ=UTC python3 verify/ref_python.py fixtures/generated/main.txt /tmp/out
cp /tmp/out/trace.jsonl /tmp/out/snapshot.json fixtures/golden/flag_off/
shasum -a 256 fixtures/generated/main.txt fixtures/golden/flag_off/*   # update CHECKSUMS
```

Then re-run `verify/run_scenarios.sh` and the full replay suite, because a
golden change usually means the engine changed.

## Adding real recordings

Real captures from `scripts/csi_recorder.py` may be added only after all of
this holds:

1. every BSSID / MAC replaced with a documentation-range address;
2. timestamps rebased onto the synthetic `BASE_US` epoch, so no wall-clock
   date, time of day or session length survives;
3. reviewed for anything that reveals the home layout — room counts, furniture
   signatures, occupant schedules, device names in tags;
4. the capture is released for this purpose by whoever recorded it.

Until then this directory stays synthetic-only.

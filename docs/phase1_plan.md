# 阶段 1：WiFi CSI 可行性验证（第 1–2 周）

目标：用最低成本回答一个问题——**ESP32-S3 的 CSI 能不能稳定区分「无人 / 有人静止 / 有人运动」**。这是后面所有跌倒判定的地基。跑不通这一步，后面的算法都没意义。

## 1. 采购清单（价格为估算，以实际为准）

| 物品 | 数量 | 说明 | 预估 |
|---|---|---|---|
| ESP32-S3-DevKitC-1（建议 N16R8） | 4 | 2 个做主验证，2 个备用/做多链路 | 30–50 元/块 |
| 数据线（带数据传输）+ 5V 电源头 | 4 套 | 部署后需要独立供电 | 20–40 元 |
| 一台旧路由器/独立 AP（2.4GHz） | 1 | 单独组网，不连其他智能设备，避免拥塞干扰 | 已有则 0 |
| 三脚架/支架或胶带 | 若干 | 固定节点高度与朝向，保证可重复 | 20 元 |
| 软垫/瑜伽垫 | 1 | 后期跌倒模拟用，务必保护志愿者 | 已有则 0 |

合计约 300 元以内。笔记本电脑用来烧录和采集。

## 2. 环境搭建

1. 安装 ESP-IDF（按乐鑫官方 Programming Guide 安装，版本以 esp-csi 仓库 README 要求为准）。
2. 克隆仓库：`git clone https://github.com/espressif/esp-csi`
3. 仓库里与本阶段相关的目录：
   - `examples/get-started/csi_send`：发送端
   - `examples/get-started/csi_recv`：接收端
   - `examples/get-started/csi_recv_router`：用路由器当发送端，ESP32 通过 ping 触发路由器回包并读取 CSI
   - `examples/get-started/tools`：数据解析脚本（如 `csi_data_read_parse.py`）
   - `examples/esp-radar/console_test`：带交互控制台和实时可视化，内置有人/无人、运动/静止检测
4. 烧录示例（以 S3 为例，串口号按系统调整；macOS 通常是 `/dev/cu.usbmodem*`）：

```bash
cd esp-csi/examples/get-started/csi_send
idf.py set-target esp32s3
idf.py flash -b 921600 -p <串口> monitor

cd ../csi_recv
idf.py set-target esp32s3
idf.py flash -b 921600 -p <另一个串口>
```

注意：运行上位机可视化工具前，要先关闭 `idf.py monitor`，否则串口被占用。

## 3. 两种取 CSI 的方式，两种都试

- **方式 A：设备间（csi_send → csi_recv）**。不依赖路由器，稳定性更好，也更接近未来的产品形态（自带节点）。需要至少 2 块 ESP32。
- **方式 B：路由器当发送端（csi_recv_router）**。只要 1 块 ESP32 加路由器，但效果受路由器位置和协议影响。用来评估「能否真的利用现有路由器」。

结论预期：方式 B 用来验证「零新增硬件」是否可行，大概率会发现不稳定，这个结论本身就有价值。

## 4. 实验设计（每个实验记录：房间、节点位置/高度、距离、时间）

固定变量：信道（固定在 2.4GHz 干扰较小的信道）、节点高度（建议 1–1.5 m）、发送速率。

| 编号 | 实验 | 做法 | 看什么 |
|---|---|---|---|
| E1 | 空房间基线 | 无人 10 分钟，关风扇/空调摆页 | 基线噪声水平、波动范围 |
| E2 | 有人静止 | 坐/躺在不同位置各 5 分钟 | 与基线能否分开 |
| E3 | 有人运动 | 走动、做家务动作各 5 分钟 | 与静止能否分开 |
| E4 | 干扰源 | 开风扇、窗帘飘动、宠物走动、邻居手机开热点 | 误判情况 |
| E5 | 换房间 | 客厅、卧室、卫生间各重复 E1–E3 | 阈值/模型能否迁移 |
| E6 | 跌倒模拟（先别急） | 软垫上模拟下蹲、坐倒、倒地，保持不动 30 秒 | 「剧烈动作 + 随后静止」是否可区分 |

每次采集都要同步记录标签（开始/结束时间、动作类型）。可用手机秒表加表格，后期再升级成脚本自动打标。

## 5. 阶段通过标准（建议）

- E2/E3：有人静止 vs 运动的区分，在同一房间内召回率 ≥ 90%
- E1：空房间连续 1 小时无人，误判「有人」次数 ≤ 1 次
- E5：换一个房间，不重新调参时指标下降幅度在可接受范围内（记录下降多少，这是泛化能力的第一个数据点）
- 方式 A 与方式 B 的稳定性差异有明确结论

没达到标准不是失败，是重要结论：要么调整节点布局/信道，要么提前引入毫米波作为主传感器。

## 6. 下一阶段预告（阶段 1 通过后）

1. 跌倒判定逻辑：剧烈变化 → 持续静止 → 无应答 → 通知（避免只做动作分类）
2. 自动校准：安装后几天自动学习环境基线
3. 家属端告警：对接现有小程序订阅消息和后端，记录事件与误报反馈
4. 3–5 户试点，统计每户每月误报次数

## 7. 注意事项

- 跌倒模拟务必有人在旁保护，使用软垫，由年轻志愿者做，不要让老人参与测试。
- 采集前告知家人，数据只存本地，不上传。
- 记录所有实验的环境照片和布局示意（不要拍人），后面复现和排查问题会用到。

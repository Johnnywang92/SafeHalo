## 2. 硬件链路极速自检 (Smoke Test)

插入 ESP32-S3 探针后，在网关或测试电脑上运行专用巡检工具：

```bash
# 自动扫描并对已连接探针进行全项体检
python3 scripts/hardware_probe_doctor.py --mac "主路由MAC地址"
```

**自检合格基准**:
- [ ] **串口握手**: 成功在 921600 波特率下打开 `/dev/ttyUSB0` (或 `/dev/cu.usb*`)；
- [ ] **稳定采样率**: 稳态数据帧率维持在 **28 ~ 32 Hz**；
- [ ] **射频 RSSI**: 信号平均强度 $\ge -68\text{ dBm}$（严禁弱于 $-72\text{ dBm}$）；
- [ ] **频宽规范**: 每一帧 CSI 数据长度为 104 字节（严格对应 **52 个 OFDM 子载波**，I/Q 分量完整）；
- [ ] **双向激振握手**: 下发 `BURST_RATE:100` 后，帧率跳变至 **90 ~ 100 Hz**。

## 3. 七大核心验收用例实操协议 (TC-1 ~ TC-7)

### TC-1: 冷启动与 5 秒全屋静默标定
* **测试目的**: 验证多径消除矩阵对房间静态背景散射特征的自动消除。
* **实操步骤**:
  1. 保证房间内完全无人（或长辈在床上静止），设备通电启动；
  2. 观察控制台首页或 CLI 输出；
* **预期现象**:
  - 前 5 秒显示 `CALIBRATING`；
  - 5 秒后状态平稳跳转至 `EMPTY`（空房）或 `STATIC`（静态驻留）；
  - `base_variance` 稳定收敛于 $< 0.005$；
* **实测记录**: 标定耗时：______ 秒，收敛底噪：______，判定：[ ] 通过 / [ ] 不通过

---

### TC-2: 日常生活动作抗扰与零误报验证
* **测试目的**: 验证正常起居动作不会被误判为跌倒。
* **实操步骤**:
  1. 受试者在房间内大步快走 2 分钟；
  2. 受试者快速坐在沙发或床上 3 次；
  3. （如有宠物）让猫/狗在地面跑动 1 分钟；
* **预期现象**:
  - 快走时系统稳定输出 `MOVING`；
  - 坐下时可能有瞬时微动，但不会进入倒地持续静止；
  - 宠物活动时系统正确标记为 `PetActivity`；
  - **全程 0 跌倒误报、0 告警通知**；
* **实测记录**: 快走误报数：0，快速坐下误报数：0，防宠物识别：[ ] 正常，判定：[ ] 通过 / [ ] 不通过

---

### TC-3: 软垫受控跌倒冲击与激振提频响应
* **测试目的**: 验证初筛冲击捕捉、定向激振提频及胸腔微动检测。
* **实操步骤**:
  1. 在监控区域中央铺设 10cm 厚安全软垫；
  2. 受试者后仰或前倾倒在垫上，并**完全保持倒地静止**；
* **预期现象**:
  - 跌倒瞬间（$\le 1$ 秒）尖峰能量触发，状态切换为 `FALL_SUSPECT`；
  - 射频节点立即收到 `BURST_RATE:100`，采样率激振提升至 100Hz；
  - 定向排查器启动 3~5 秒地面微动核验；
  - 倒地静止超过阈值后，状态跃迁至 `FALL_CONFIRMED` 并触发红字告警；
* **实测记录**: 冲击响应延迟：______ 秒，激振最高帧率：______ Hz，判定：[ ] 通过 / [ ] 不通过

---

### TC-4: 本地轻度安全质询应答与就地平稳解除
* **测试目的**: 验证老人轻微摔倒但意识清醒时，“不惊扰家属”的温和化解能力。
* **实操步骤**:
  1. 受试者执行坐地动作进入 `FALL_SUSPECT` 质询窗口；
  2. 机身发出轻微安全质询蜂鸣声（如“如您安全请轻动一下”）；
  3. 受试者按下机身按键，或在 Web 界面点击【我没事】；
* **预期现象**:
  - 控制台立即记录 `CHALLENGE_ACK`（安全应答确认）；
  - 状态平稳退回 `MOVING`，疑似跌倒告警就地解除；
  - **千里之外的家属手机微信与 Bark 不弹出打扰通知**；
* **实测记录**: 应答解除响应时间：______ 秒，家属免打扰验证：[ ] 成功，判定：[ ] 通过 / [ ] 不通过

---

### TC-5: 串口物理热拔插与自动自愈长稳
* **测试目的**: 验证老人踢碰 USB 线缆或松动脱落时的自愈鲁棒性。
* **实操步骤**:
  1. 系统正常运行时，直接拔掉 ESP32-S3 的 USB 数据线；
  2. 观察控制台状态；
  3. 5 秒后将 USB 线重新插入同一或相邻 USB 口；
* **预期现象**:
  - 拔出后 $\le 2$ 秒，状态显示为 `ROUTER_OFFLINE`，守护进程**绝不崩溃**；
  - 重新插入后 $\le 2$ 秒，守护进程通过串口热扫描自动重新握手，无需重启系统自动恢复 `CALIBRATING` $\to$ `EMPTY`；
* **实测记录**: 断开捕获延迟：______ 秒，重连自愈耗时：______ 秒，判定：[ ] 通过 / [ ] 不通过

---

### TC-6: 路由器重启与断网弱信号恢复
* **测试目的**: 验证外网中断时通知队列的持久化重试保障。
* **实操步骤**:
  1. 拔掉路由器的 WAN 口外网网线（模拟家庭宽带欠费或光猫断电）；
  2. 在室内触发一次跌倒告警；
  3. 观察守护进程日志与 `pending_notifications.jsonl`；
  4. 30 秒后插回外网网线；
* **预期现象**:
  - 断网期间通知进入指数退避重试队列，未丢失；
  - 外网恢复后，告警在下一次重试周期内**全量自动补发**至家属手机；
* **实测记录**: 队列持久化恢复：[ ] 正常，补发成功率：100%，判定：[ ] 通过 / [ ] 不通过

---

### TC-7: 移动端多通道与 iOS Bark 强提醒突破
* **测试目的**: 验证夜间睡眠专注模式与静音开关下能否有效唤醒家属。
* **实操步骤**:
  1. 家属 iPhone 打开机身实体静音开关（红色静音）；
  2. 下拉控制中心打开【睡眠专注模式 / 勿扰模式】；
  3. 在控制台点击【发送测试告警】；
* **预期现象**:
  - iPhone 屏幕自动亮屏唤醒，突破勿扰模式；
  - 以高音量（Volume 10）播放警报声音；
  - 通知卡片完整显示跌倒位置、实测呼吸估计（如 18 bpm）与事件编号；
  - 微信服务通知（PushPlus）同步弹窗；
* **实测记录**: 静音突破响铃：[ ] 成功，呼吸率字段展示：______ bpm，判定：[ ] 通过 / [ ] 不通过
